# 多用户求职 Web 应用设计

## 1. 目标

将当前面向单个候选人的本地求职辅助工具扩展为邀请制、多用户 Web 应用，服务 2～10 人的本机试点，并按公网可部署架构设计。

第一版以 BOSS 直聘为唯一试点平台，验证完整闭环：

```text
邀请注册 -> 上传资料 -> AI 提取画像 -> 用户确认
-> 配置搜索模板 -> 连接 BOSS 浏览器
-> 采集岗位 -> 用户独立筛选评分
-> 多选岗位 -> 批量生成草稿
-> 逐个审核 -> 生成 DOCX/PDF
```

## 2. 已确认范围

- 使用 FastAPI 后端 API + React 前端。
- 本地运行，架构预留公网部署能力。
- SQLite 作为第一版数据库，数据访问层保持 PostgreSQL 兼容。
- 本机使用 MinIO，未来可切换 S3、OSS 或 COS。
- 邀请制注册，一次性邀请链接或邀请码。
- 第一版不接邮件找回，管理员手动重置密码。
- 普通用户严格私有，管理员默认不能读取用户内容。
- 公共职位基础信息共享；评分、收藏、排除、备注、材料和申请状态按用户隔离。
- 用户上传 PDF、DOCX、Markdown 或纯文本，由云端模型提取画像建议，用户确认后写入正式画像。
- 首次使用 AI 功能时，用户明确同意数据处理；设置中可以撤回或关闭。
- 管理员提供默认模型 API Key，用户可以配置自己的 Key；用户 Key 优先使用。
- 用户可以自定义职位、行业、城市、关键词、学历、经验、薪资和工作方式，并保存搜索模板。
- 系统提供默认评分规则，用户可以修改自己的硬性筛选条件和权重。
- 系统提供默认中文简历和求职信模板，用户可以上传或配置自己的模板。
- 用户可以在评分结果中勾选多个岗位，批量生成草稿，再逐个审核。
- BOSS 使用每个用户独立的 Chromium 用户目录；用户自行完成登录，系统只读采集。
- 登录过期、验证码、限流或风控状态进入人工暂停，不以空结果表示成功。
- 第一版不实现平台投递、简历上传、聊天、自动回复等平台写操作。

## 3. 总体架构

```text
React 前端
  -> FastAPI REST API
       |- 认证与邀请
       |- 候选人画像与资料
       |- 搜索模板与岗位查询
       |- BOSS BrowserConnector
       |- 用户评分与筛选
       |- 批量材料任务
       |- 文件对象管理
       `- 管理员配置
  -> SQLite
  -> MinIO
  -> 独立 Chromium Profile
```

应用采用模块化单体，按接口隔离未来替换点：

- `BrowserConnector`：第一版连接本机 Chromium Profile，后续可替换为用户本地 Agent。
- `LLMProvider`：支持管理员默认 Key 和用户自有 Key。
- `ObjectStorage`：第一版 MinIO，未来切换 S3 兼容服务。
- `TaskRunner`：第一版 FastAPI 后台任务，未来切换 Redis + Celery/RQ。
- `Repository`：屏蔽 SQLite/PostgreSQL 差异，并强制注入当前用户过滤条件。

## 4. 租户和数据模型

### 4.1 共享数据

`jobs` 保存公共岗位基础数据：平台、平台职位 ID、标题、公司、地点、薪资、描述、URL、抓取时间、过期时间和解析版本。

公共岗位通过 `source + external_job_id` 或规范化 URL 去重。共享缓存不包含任何用户画像、评分或申请记录。

### 4.2 用户数据

建议实体：

- `users`：账户、角色、状态、密码哈希。
- `invites`：邀请码或邀请链接、过期时间、使用状态。
- `candidate_profiles`：画像版本和确认状态。
- `source_documents`：用户原始资料的 MinIO 对象元数据。
- `search_templates`：用户搜索关键词和筛选规则。
- `user_job_evaluations`：评分、硬过滤结果、收藏、排除、备注和评分规则版本。
- `material_batches`：一次批量材料任务。
- `material_drafts`：用户与岗位对应的简历/求职信草稿及审核状态。
- `file_objects`：MinIO 对象 Key、哈希、类型、大小、所属用户和状态。
- `applications`：用户自己的申请记录。
- `tasks`：采集、解析、评分、生成等任务状态和错误摘要。
- `model_credentials`：加密后的用户模型 Key。
- `browser_sessions`：用户 Chromium Profile 路径、状态和最后使用时间，不保存密码。

### 4.3 隔离规则

- 所有用户私有实体必须携带 `user_id`。
- 私有查询由服务端从认证上下文取得 `user_id`，不信任前端传入的所有者 ID。
- 管理员只能管理邀请码、账户状态、密码重置、系统配置和任务健康状态。
- 管理员默认不能查询用户画像、原始文件、评分结果、草稿和申请记录。
- MinIO 对象使用 `users/{user_id}/...` 前缀，下载必须经过后端授权。
- SQLite 阶段由 Repository 层执行租户过滤；PostgreSQL 阶段可增加数据库级策略。

## 5. 用户流程

### 5.1 注册和画像

1. 管理员生成一次性邀请链接或邀请码。
2. 用户设置账号和密码。
3. 用户首次使用 AI 功能时确认数据处理授权。
4. 用户上传 PDF、DOCX、Markdown 或纯文本。
5. 系统将文件保存到 MinIO，创建画像提取任务。
6. 云端模型提取教育、经历、项目、技能和偏好，生成变更建议。
7. 用户确认建议后写入画像版本；未确认内容不得进入正式画像。

### 5.2 搜索和评分

1. 用户创建或选择自己的搜索模板。
2. 用户点击连接 BOSS，系统启动独立 Chromium Profile。
3. 用户在浏览器中完成 BOSS 登录。
4. 后台任务按模板采集岗位并写入共享 `jobs`。
5. 登录失效、验证码、限流或风控时，任务进入 `paused`，等待用户处理。
6. 系统使用当前用户画像和评分规则生成私有 `user_job_evaluations`。
7. 前端显示评分、匹配理由、差距、薪资参考、城市层级和风险标记。

### 5.3 批量材料

1. 用户在评分列表中勾选多个岗位。
2. 系统创建一个批量任务和每个岗位的子任务。
3. 每个岗位独立生成简历和求职信草稿。
4. 用户逐个审核事实、匹配理由和岗位定制内容。
5. 审核通过后生成最终 DOCX/PDF。
6. 审核不通过的岗位可单独修改或重新生成，不影响其他岗位。

## 6. 后端接口边界

接口模块：

```text
/auth
/invites
/profile
/documents
/search-templates
/browser-sessions
/jobs
/evaluations
/material-batches
/material-drafts
/applications
/settings
/admin
```

任务状态统一为：

```text
queued -> running -> completed
                 |- paused
                 `- failed
```

验证码、登录失效和人工处理状态不自动重试；网络瞬态错误可以按次数限制重试。

## 7. 前端页面

普通用户页面：

- 邀请注册、登录和账户设置。
- 资料上传和画像变更审核。
- 搜索模板管理。
- BOSS 连接状态和人工处理提示。
- 岗位列表、筛选、排序、收藏、排除和多选。
- 评分详情、匹配理由和风险标记。
- 批量草稿任务进度。
- 单岗位草稿审核和最终文件下载。
- 申请记录和材料历史。

管理员页面：

- 邀请码生成、撤销和使用状态。
- 用户启用、停用和密码重置。
- 默认模型配置。
- 任务运行状态和错误统计。

管理员页面不提供用户私有内容浏览入口。

## 8. 存储和部署

本机试点组件：

```text
React dev server
FastAPI
SQLite
MinIO
Chromium
```

建议使用 Docker Compose 管理 FastAPI、React 和 MinIO；SQLite 文件和 Chromium Profile 使用本地挂载目录。

未来公网迁移：

- SQLite -> PostgreSQL。
- MinIO -> S3/OSS/COS。
- FastAPI BackgroundTasks -> Redis + Celery/RQ。
- 服务器 Chromium Profile -> 用户本地浏览器 Agent/连接器。
- 增加 HTTPS、邮件找回、限流、审计和更强认证。

## 9. 测试和验收

### 9.1 测试范围

- 邀请制注册、登录、密码哈希和权限拒绝。
- 用户 A 无法读取用户 B 的画像、文件、评分、草稿和申请记录。
- 同一共享岗位可以被多个用户评分，但评分结果互不可见。
- 用户资料上传、AI 提取建议、确认写入和版本回滚。
- BOSS BrowserConnector 的连接、断开、登录失效和暂停状态。
- 公共岗位去重、缓存过期、字段标准化和来源追踪。
- 用户自定义搜索模板和评分权重。
- 多岗位勾选、批量草稿、逐项审核和单项重试。
- DOCX/PDF 生成、中文文本提取、文件授权下载和材料归档。
- API Key 加密存储、用户 Key 覆盖默认 Key 和授权撤回。

### 9.2 第一阶段验收标准

1. 至少创建 2 个用户，私有数据完全隔离。
2. 两个用户可以看到同一公共岗位，但评分和操作记录不同。
3. 每个用户可以独立上传资料并确认自己的画像。
4. 每个用户可以创建不同的搜索模板和评分权重。
5. BOSS 登录异常不会伪装成空职位列表。
6. 一个用户可以一次勾选多个岗位并生成多个草稿。
7. 用户可以逐个审核草稿，单个岗位失败不影响批次其他岗位。
8. 审核通过后能生成该用户自己的 DOCX/PDF。
9. 管理员可以管理邀请和密码，但不能读取用户私有内容。
10. 不执行平台投递、上传、聊天或回复操作。

## 10. 不纳入第一版

- BOSS 自动投递、自动上传简历、自动聊天和自动回复。
- 163、QQ、企业邮箱状态同步。
- Notion 等外部同步。
- 多平台同时接入；其他平台通过同一岗位适配器接口后续增加。
- 公网正式部署、邮件找回和多因素认证。
- Redis/Celery 分布式任务队列。
- 用户本地 Agent；第一版使用本机独立 Chromium Profile。
