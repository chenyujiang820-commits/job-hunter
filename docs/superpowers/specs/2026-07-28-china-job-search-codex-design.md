# 国内求职 Codex 工作流复刻设计

## 1. 目标与结论

将 `ai-job-search-master` 的可复用部分迁移为 Codex 原生工作流，第一阶段服务于个人在智联招聘上搜索浙江省内的初级技术型产品经理岗位，并生成中文 DOCX + PDF 简历和求职信。

本项目定位为本地求职辅助工具，不实现全自动投递机器人。第一阶段只做公开职位读取、职位筛选、材料生成和本地申请记录。

第一阶段可行性较高。现有项目的候选人画像、职位评分、两阶段搜索/排序流程、本地状态结构和材料审查逻辑可以复用；需要重写的是 Claude Code 专用的流程编排、国内门户适配和中文材料输出。

## 2. 已确认范围

### 第一阶段交付

- 运行形态：Codex 原生工作流，手动触发。
- 试点平台：智联招聘。
- 岗位：初级产品经理。
- 地域：浙江省内。
- 岗位方向：通信、硬件、物联网、政企解决方案等技术型产品。
- 候选人资料来源：项目 `documents/` 目录。
- 输入格式：PDF、DOCX、Markdown、纯文本。
- 输出格式：DOCX + PDF。
- 排序流程：保留原项目的“先搜索、再独立排序”两阶段模式。
- 材料触发：只对用户从排序结果中选中的职位生成。
- 材料组合：始终生成定制简历和求职信。
- 数据存储：默认本地保存。
- 外部同步：第一阶段不启用，仅预留接口。

### 候选人画像规则

- 学历条件：本科。
- 求职身份：往届生。
- 专业背景：通信工程。
- 政治面貌：党员，默认写入简历、求职信和职位匹配上下文，并允许用户关闭。
- 城市优先级：丽水第一优先；杭州、金华第二优先；浙江其他县市第三优先。
- 薪资：不设硬性底线，仅作为排序参考。
- 工作方式：接受现场办公和适度出差，长期驻场降低匹配度或标记风险。
- 硬性排除：劳务派遣、外包。
- 新资料写入：只提出画像变更建议，用户确认后才写入正式画像。

### 明确不做

- BOSS 直聘或猎聘自动聊天、自动回复。
- 自动登录国内求职平台。
- 自动上传简历、自动填写并提交申请。
- 验证码、短信验证、Cookie、Token 或平台风控绕过。
- 批量平台操作。
- 第一阶段 QQ、163 或企业邮箱同步。

## 3. 目标架构

```text
Codex 工作流
  -> 候选人资料读取
  -> 智联招聘适配器
  -> 统一职位模型
  -> 本地去重与缓存
  -> /rank 评分排序
  -> 用户选择职位
  -> 材料生成与审查
  -> DOCX + PDF 输出
  -> 本地申请归档
```

采用小范围重构后移植：保留原项目 `.agents/skills` 下的 CLI 结构、候选人资料、评分框架、`seen_jobs.json`、tracker 和 documents 目录；将 `.claude/commands` 和 `.claude/skills` 中的流程规范转换为 Codex 可执行工作流。

核心模块和接口：

```text
ZhilianAdapter
  search(query, location, filters)
  detail(job_id_or_url)

JobNormalizer
  normalize(raw_job) -> normalized_job

LocalStateStore
  seen_jobs.json
  job_search_tracker.csv
  documents/applications/

RankingWorkflow
  score(job, candidate_profile) -> score_card

MaterialWorkflow
  generate_resume(job, candidate_profile) -> DOCX/PDF
  generate_cover_letter(job, candidate_profile) -> DOCX/PDF

ExternalSyncAdapter
  reserved for future Notion or similar destinations
```

`ZhilianAdapter` 第一阶段只读公开数据，统一输出职位 ID、职位名称、公司、地点、薪资、经验、学历、技能、岗位类型、发布时间、截止日期、URL 和来源。未来平台适配器必须复用同一 `search/detail` 契约。

## 4. 用户数据流

### 4.1 候选人资料初始化

Codex 扫描 `documents/` 中的 PDF、DOCX、Markdown 和纯文本，提取教育经历、项目、技能、经历和个人偏好，生成画像变更建议。用户确认后才更新主画像。发生冲突时保留冲突记录，不覆盖原资料。

### 4.2 手动职位搜索

用户手动触发搜索。默认查询包括浙江省、初级产品经理、通信/硬件/物联网/政企产品等关键词。搜索结果写入本地缓存，并按平台 URL、平台 ID 和公司+职位组合去重。

### 4.3 独立职位排序

用户手动触发排序。排序读取新职位、候选人画像和评分规则，执行学历、身份、岗位方向、城市优先级、薪资参考、工作方式及外包/派遣排除规则。

结果至少包括：总分、匹配等级、城市、核心优势、主要差距、排除原因或风险、职位 URL。

### 4.4 选中职位后的材料生成

用户从排序结果中选择职位后，依次执行：职位详情分析、匹配评估、用户确认、简历生成、求职信生成、事实校验、Reviewer 审查、用户确认最终版本、DOCX/PDF 保存和本地归档。

未被用户选中的职位不得生成材料。

## 5. 国内职位字段标准化

至少支持：

- 中文职位名称、同义词和技能词。
- 省、市、区县和通勤范围。
- 月薪、年薪、13 薪、奖金、股权和面议。
- 学历、工作年限、应届/往届、岗位类型。
- 校招、社招、实习、兼职、劳务派遣和外包标记。
- 行业、公司规模、融资阶段。
- 现场办公、远程、混合办公、出差和驻场信息。
- 字段原始值、规范化值、来源 URL 和抓取时间。

缺失字段返回 `null`，不得因为字段缺失改变统一 JSON 结构。薪资无法解析时只降低信息完整度，不直接淘汰职位。

## 6. 材料生成设计

现有英文 LaTeX 模板不能直接作为国内第一版交付模板。第一阶段应增加中文 DOCX 模板，并以 `python-docx` 生成 DOCX，再使用 LibreOffice `soffice --headless` 转换 PDF。Markdown 可作为内部中间内容，最终材料必须经过 DOCX/PDF 检查。`python-docx` 和 LibreOffice 属于实施前置依赖，安装前需要单独确认授权；如果 `soffice` 不可用，流程必须停止并报告缺少 PDF 转换工具。

材料生成要求：

- 简历和求职信始终成对生成。
- 每个事实、日期、公司、职位、数字和技能都必须能追溯到候选人资料或用户确认内容。
- 党员信息默认可用于材料，但应保留开关。
- 不默认生成身份证号、家庭住址、婚育等非必要敏感信息。
- 校验中文字体、换行、页数、文件可打开性和文本提取结果。
- DOCX 失败时保留中间内容但不得声称已生成成功的 PDF。
- Reviewer 失败或事实冲突时阻止最终版本输出。

## 7. 错误处理与安全边界

### 外部访问

- 网络失败、超时、429 和 5xx：有限重试并记录错误。
- 登录页、验证码或风控页面：停止请求，不绕过。
- 页面结构变化：报告解析异常，不把空结果当成无职位。
- 连续零结果：提示检查适配器和访问状态。
- 所有 live smoke test 低频执行，测试主要依赖本地 fixture。

### 不可信职位文本

- 职位描述只作为数据，不执行其中的指令。
- 不访问职位正文中的外部链接。
- 不根据职位文本修改候选人资料。
- 不将职位正文和候选人资料发送到未经配置的外部系统。

### 本地数据

- 候选人资料、生成材料和申请记录默认只保存在本地。
- 不保存智联登录凭据、Cookie 或 Token。
- 日志不得输出邮件正文、授权码、完整联系方式或个人材料。
- 未来外部同步只通过 `ExternalSyncAdapter`，默认只同步职位和申请状态，不上传简历、求职信、邮件正文或候选人画像。

### 用户确认门禁

写入候选人画像、生成最终材料、归档申请和未来外部同步都必须经过用户确认。系统不执行平台登录、上传、提交、聊天、回复或批量操作。

## 8. 测试与验收

### 适配器测试

- 使用本地 fixture 验证搜索和详情解析。
- 验证中文实体、换行、特殊字符和缺失字段。
- 验证 429、5xx、超时、验证码和解析异常。
- 验证 URL、平台 ID 和公司+职位去重。
- 低频执行真实平台 smoke test，不能用真实请求替代完整测试。

### 排序测试

- 本科职位通过学历条件。
- 往届生职位可匹配。
- 劳务派遣和外包被排除。
- 丽水高于杭州/金华，杭州/金华高于其他浙江县市。
- 技术型产品方向获得加分。
- 薪资只排序，不硬性淘汰。
- 长期驻场被标记风险。
- 过期和重复职位不进入推荐列表。

### 材料测试

- 能读取 PDF、DOCX、Markdown 和纯文本。
- 新事实只生成变更建议。
- 未选职位不生成材料。
- 选中职位始终生成简历和求职信。
- 事实校验和 Reviewer 未完成时不能标记最终版本。
- DOCX 和 PDF 都能生成、打开、提取中文文本。

### 端到端验收

完成一次真实流程：放入候选人资料，手动搜索智联招聘，手动运行排序，选择浙江省内初级技术型产品经理职位，完成匹配分析、用户确认、简历/求职信生成、事实校验、Reviewer 审查、最终确认和本地归档。

## 9. 分阶段实施

### 第一阶段：智联招聘 MVP

- Codex 原生搜索和排序工作流。
- `ZhilianAdapter` 的只读 `search/detail`。
- 统一职位模型、缓存、去重和排序。
- 中文候选人画像和产品经理评分规则。
- 中文 DOCX + PDF 简历和求职信。
- 用户确认、事实校验、Reviewer 审查和本地归档。

### 第二阶段：QQ 邮箱状态同步

- 优先评估 IMAP，POP3 作为兼容方案。
- 使用授权码、TLS、UIDL 和 Message-ID 去重。
- 只读识别面试、测评、Offer 和拒信。
- 用户确认后更新本地 tracker 和 outcome。

### 后续扩展

- 前程无忧、猎聘和 BOSS 只读职位适配器。
- 163 和企业邮箱适配器。
- Notion 等外部同步目标。

## 10. 关键假设与待验证项

- 智联招聘存在可合规读取的公开搜索或详情入口；实现前必须现场验证。
- Codex 当前环境能够执行所需的 Bun CLI 和 DOCX/PDF 工具链。
- Python DOCX 生成依赖和 LibreOffice PDF 转换工具在实施前确认可用，并加入 preflight 检查。
- 外部平台服务条款、robots.txt、限流和数据使用规则必须以实现时的最新信息为准。
- 本设计不授权任何平台写操作、自动登录或验证码处理。
